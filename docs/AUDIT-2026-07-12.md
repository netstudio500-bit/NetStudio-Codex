# Auditoria técnica de execução — 2026-07-12

## Veredito

Estado atual: **fundação funcional, integração incompleta**.

O `Agent` já executa chamadas reais por meio de `LLMProvider`, usa `OllamaProvider` por padrão e injeta memória curta de sessão no prompt. Porém, o ponto de entrada ainda não monta um fluxo operacional de agente. A CLI inicializa configuração e encerra sem criar agente, receber tarefa ou executar ferramentas.

## Achados

### CRÍTICO — CLI não inicia o agente

`netstudio/main.py` contém uma inicialização placeholder. O comando `python -m netstudio.main` não cria `Agent` nem executa uma tarefa.

**Impacto:** o caminho principal documentado no README não entrega uma experiência de agente utilizável.

**Ação recomendada:** transformar a CLI no primeiro vertical slice real: entrada de tarefa -> Agent -> Ollama -> resposta -> encerramento seguro.

### ALTO — Capacidades documentadas excedem o estado comprovado

O README apresenta memória persistente, recuperação automática, UI web, runtime, planner e registry de ferramentas como módulos/capacidades do produto. A auditoria atual comprova apenas a base de configuração, logging, provider Ollama e agente mínimo conectado ao provider.

**Impacto:** novos contribuidores podem interpretar roadmap como funcionalidade entregue.

**Ação recomendada:** separar claramente `Disponível agora` de `Planejado`.

### ALTO — Ferramentas ainda não participam do ciclo do agente

O agente atual gera texto diretamente pelo provider. Não existe, no fluxo auditado, um loop de decisão estruturada que selecione ferramenta, execute-a, valide o resultado e devolva observação ao modelo.

**Ação recomendada:** implementar um `AgentRuntime` mínimo e explícito antes de expandir quantidade de ferramentas.

### MÉDIO — Memória é apenas em processo

`Agent._memories` mantém as dez últimas entradas no processo atual. Isso é útil como contexto curto, mas não é memória persistente.

**Ação recomendada:** renomear a promessa documental ou implementar um backend de persistência com interface própria.

## Ordem de implementação recomendada

1. CLI funcional com argumento de tarefa e modo interativo.
2. `AgentRuntime` com ciclo limitado e estados explícitos.
3. `ToolRegistry` e contrato de ferramenta.
4. Ferramenta shell com política de execução e timeout.
5. Loop `decisão -> ferramenta -> observação -> decisão`.
6. Persistência de sessão/memória.
7. Recovery/checkpoints.
8. UI web somente após o runtime estar estável.

## Critério de pronto do próximo marco

O próximo marco deve permitir executar localmente uma tarefa simples pelo terminal, usar Qwen/Ollama de verdade, retornar uma resposta e encerrar sem depender de mocks. Para tarefas com ferramenta, o runtime deve limitar iterações, registrar ações e propagar erros de forma legível.
